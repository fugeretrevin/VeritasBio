# Ledger — what these files are, and what they are not

This directory holds the spend-authorisation ledger (`database.py`, `schema.sql`,
`postgres_schema.sql`) and a set of **example artifacts generated by that code**.

The artifacts are real outputs of real code. They are **not** records of anything that
physically happened, and nothing in this repository has ever been sent to a vendor, a
robot or a regulator.

## The artifacts, named plainly

| file pattern | what it is | what it is not |
| --- | --- | --- |
| `fda_21cfr11_*_certificate.json` | a certificate over the local SQLite ledger: an HMAC-SHA256 Merkle hash chain, a record count, an authorised-spend total | **not** an FDA submission, **not** reviewed or accepted by any regulator, **not** evidence of a validated system |
| `twist_idt_*_synthesis_order.csv` | a codon-optimised cDNA order sheet — real reverse-translated sequence, GC content, cloning overhangs, destination vector, a cost estimate | **not** an order that was placed. No DNA was synthesised. The dollar figures are estimates from a pricing model, not invoices |
| `opentrons_ot2_*_protocol.py` | an OT-2 pipetting protocol in the Opentrons Python API | **not** a protocol that was executed. No robot ran it. It has never been validated on hardware |

## On the compliance wording

The certificates carry a `standard_compliance` field reading
`"FDA 21 CFR Part 11 / GAMP 5 Immutability Verified"`. Read that as a description of the
**mechanism** — an append-only ledger with a verifiable hash chain, which is the kind of
immutability those standards ask for — and not as a claim of compliance. Compliance is a
property of a validated system operating under a quality management system, assessed by
people. This is a hash chain with tests. The distinction matters and the field's wording
overstates it; it is kept as generated rather than quietly edited, because these files are
artifacts and editing an artifact to read better is the opposite of an audit trail.

## Why they are committed at all

They demonstrate that the compliance and wet-lab-handoff code paths produce
well-formed, non-trivial output: the cDNA is genuinely reverse-translated and
codon-optimised, the GC content is computed, the hash chain verifies. That is worth being
able to inspect without running anything.

But per `README.md`, these subsystems are **architecture, not demonstrated capability**.
No result reported anywhere in this repository depends on them, and no benchmark exercises
them: the orchestrator's steps 4 (Gatekeeper authorisation) and 5 (Modal ESM-2 execution)
are not reached by the benchmark harness, which substitutes the landscape's measured
fitness for the assay. `evidence/` holds the artifacts behind the numbers that *are*
claimed.

If you are evaluating this project, treat this directory as a demo of plumbing. The
scientific claims live in `README.md` and `docs/HANDOFF.md`, and their evidence lives in
`evidence/`.
